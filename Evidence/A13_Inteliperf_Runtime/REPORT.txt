INTELIPERF NATIVE-RUNNER LOCAL DEMONSTRATION
Executed 11 October 2026. Synthetic, local-only technical evidence; no client data or deployment claim.

Observed result
The existing InternalRunner executed the same one-step plan twice against a temporary loopback HTTP server. Both phases returned HTTP 200. In the first phase, JSON value was deliberately incorrect; in the second, the harness deliberately changed it to the expected value.
Before: 3 measured requests, 3 per-step assertion errors.
After: 3 measured requests, 0 per-step assertion errors.
One additional authentication-preflight probe occurred per phase: 8 server receipts in the final run, of which 6 are measured workload requests. The server receipt log independently records the phase and returned value. Both runs have execution status completed, which must not be described as all assertions passing.

What actually ran
The unchanged repository InternalRunner, its HTTP request and JSON assertion code, metrics collection, LoadControlEngine scheduling and RuntimeSafetyMonitor executed. Native fetch made real requests to a private ephemeral loopback port created by the harness; there was no k6/JMeter process or mock PerformanceTestAgent. One virtual user, three iterations per phase, two-second requested phase duration and a fifteen-second harness cutoff bounded the demonstration. Calibration was disabled; no model inference occurred. The core source hashes are recorded in raw-results.json.

Isolation and omitted integrations
The harness uses TypeScript transpile-only loading and module-level substitutes for integration seams. Database operations return empty in-memory responses and record operation types; no actual database is connected. Shared status publication, global scan registration and heartbeat are replaced with local no-op callbacks. Authentication acquisition/refresh and request-rewrite paths are guarded to fail if invoked; no-auth cleanup is a counted no-op. Real external-call interception logic runs with empty storage responses. The native fetch wrapper rejects every target except the exact private loopback endpoint.
These substitutions isolate the existing backend on port 3001 and prevent shared record changes. They mean this is a core-engine integration demonstration, not an end-to-end UI, database, authentication, worker-pool or production-safety certification. No source implementation was edited. No AGENTS.md was found in the repository ancestor or applicable backend/service directories checked.

Important interpretation
Overall HTTP/transport errors are zero in both phases, because both responses are successful HTTP 200 responses. The implementation deliberately separates assertion failures from overall transport error counts. The before/after evidence is in metrics.byStep[0].errors and the runner step log; it must not be reported as a reduction in HTTP errors. Execution status completed likewise does not mean every content assertion passed.
The target correction was an explicit harness change to a synthetic response, not AutoRemediationService. No real application fix, automated remediation, AI quality uplift, client saving or sustained benefit is established. The three samples per phase are inadequate for performance inference; recorded latencies must not be presented as a performance improvement.

Reproduction
From the distribution repository root, replacing the absolute checkout path:
INTELIPERF_REPO=/absolute/aegis-test node Evidence/A13_Inteliperf_Runtime/run-demo.cjs
Set INTELIPERF_REPO explicitly for this distributed copy.
Requires the existing sibling aegis-test repository and its installed backend dependencies. For another location, set INTELIPERF_REPO to the repository directory before running the command. The harness starts and closes its own server, writes only in this evidence directory and does not need the running application or its credentials. A rerun replaces the final raw/log output; preserve this directory first if retaining historical versions.
The current portable script adds that environment override and private-original/public-redaction output handling after the successful run. It has not been rerun because these adjustments do not alter execution or outcome checks. provenance.json distinguishes the exact executed script hash from the current portable script hash.
