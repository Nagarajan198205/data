INTELLISEC LOCAL ARCHITECTURE AUDIT — read-only, 11 October 2026

Scope and status. Inspected the primary ../IntelliSec source tree and its docs/AGENTS.md. No scan, test, model call, product edit, database query or external request was made. The documentation calls the system a 26-agent cognitive architecture; that is a design description, not evidence that every agent ran or that a client used it. Code existence establishes an implemented path, not live configuration, accuracy, adoption or client outcomes. The accompanying diagram marks optional branches with dashed arrows.

1. Input and orchestration — IMPLEMENTED IN CODE. API/CI entry paths create an AgentContext, session and selected agents; the GitHub webhook uses code-review, secrets and dependency agents, and the CI endpoint starts a background scan (src/api/main.py:13230–13310, 15834–15893; SHA256 d60efcc0d1f4e49b6456ea9693a1a0a3b7d8f5fd9ab300ab94e74299104f979d). The API's main run_hunting_session path updates session status, executes agent groups, merges findings and persists them (same file:4342–4390, 4770–4825, 4910–5055, 5180–5200). A separate AgentOrchestrator class implements planning, recon, analysis, active testing, native-agent, verification, exploitation and reporting phases, with optional team delegation (src/agents/orchestrator.py:526–680; SHA256 3d013584a6415f2b4532085b9631b78dd595e9f684d6fbb979c57f16e7f37245). These are related execution paths, not proof that every scan traverses every phase. The Celery scan task includes an atomic session-claim guard (src/workers/scan_tasks.py:31–132; SHA256 0a3d004459537cbb33f17eb8a09d61842d6826b986e62f36d543df2cee17f339).

2. Detection — IMPLEMENTED IN CODE, WITH MODE-SPECIFIC ROUTES. IntelliSec has native URL payload tests for XSS, SQL injection, SSRF, local-file inclusion and redirects (src/core/scanner.py:155–355, 413–804; SHA256 5a341580b2a84073f4f22eea86b89ff504cfaf948ef3121a1dd356f63257ae67). CodeReviewAgent scans files using own pattern, dataflow and context routines (src/agents/code_review_agent.py:1938–2277, 2592–2668, 3685–3749, 7139–7567; SHA256 c80e929ad5d406f5b3472767fef4e78c631267ed377b12de6b960f079c33111b). SCA manifest analysis and advisory lookup are in DependencyAgent (src/agents/dependency_agent.py:650–692, 925–952, 1224–1250; SHA256 602ef180d4ce38a53ba2ea3b8496edf7904b7d7fee83c8bb23c37b9972c68bf0); container-layer/package checks are local implementation (src/core/container_scanner.py:236–390, 474–627; SHA256 7f02029233eeab4a5c3d62d439fd893747ad9786bb9bec9844521108cc2545a2). These establish own detector logic, not complete coverage or effectiveness across all scan types.

3. Evidence and verification — IMPLEMENTED IN CODE; OUTCOMES UNPROVEN HERE. Findings are normalised, grouped into developer cards and risk-scored (src/api/services/finding_pipeline.py:65–105, 147–250; SHA256 ab02aa065a0f3d9c92f8d12b51e0736dc5f6d2264e184a61cbc6c6b8c55b3ccd). SAST processing applies deterministic false-positive suppression, then optional LLM challenge of surviving critical/speculative findings; uncertain AI output is not supposed to suppress automatically (src/api/main.py:4168–4265; same API hash; src/core/agentic_verifier.py:1–110, 190–310; SHA256 efd8ea2554469381021934266df0611634db1497a1f0c9766c22c29e870c204e). The security gate evaluates severity, execution, required controls/evidence and coverage and can block on incomplete or indeterminate assessment (src/core/security_gate.py:74–118, 268–328, 511–726; SHA256 7f4361da69e0130efef95f8acdb45724f6e8cccb89dfa51eefbd6dd0cfb213b9). A gate verdict is not a client release decision. Stored local certification reports noted in A10 are local workflow artifacts, not deployment or accuracy proof.

4. Expert governance and false positives — IMPLEMENTED IN CODE. Authenticated users can confirm, mark false positive, accept risk, mark fixed and reopen; the API retains history and records explicit validation signals (src/api/main.py:7249–7270, 7355–7508; same hash). A separate classification endpoint writes project-scoped learning signals. Exact recurring static-analysis false positives can become learned suppressions, while contradictory true-positive review removes an automatic suppression (same file:7920–8040; src/core/sast_fp/learning.py:1–145; SHA256 de78774d1bf4d1b5c891db116247cd202ee1f09e58115e20a6ca3bafb0037f8e). This is an implemented review/feedback mechanism, not inspected expert decisions or measured false-positive reduction.

5. ADO, remediation and closure — IMPLEMENTED AS BRANCHES, NOT ONE GUARANTEED END-TO-END LOOP. Configured Azure DevOps integration can create a per-scan parent story and finding work item, then close/reopen a linked item on portal triage (src/api/main.py:13970–14117, 7495–7511; same hash; src/core/ado_integration.py:139–228; SHA256 deb67917f705e6e374dc3ce80d7c5a3ba2e5897303197693ecb7bfcc5cf24106). This is optional and no client board transaction was inspected. Proposed code fixes can be applied to a copy and re-detected through an injected callback, but the module itself says gated post-scan wiring was future work (src/core/remediation_loop.py:1–125; SHA256 fc825a6583462bc45e7a813c923e90c42dcf8f2d15fe8f1a56e27bd2f4a83999). The API offers exact DAST request replay or a fallback re-scan (src/api/main.py:7612–7710; src/core/dast/retest.py:13–105; SHA256 36688d78119fbd2c41217dc1ec50228f8407c0dcfe5b1725892cc75ff9a60a58). On a later DAST scan, an absent finding is carried forward unless replay confirms a fix; then the code can auto-resolve and attempt ADO closure (src/api/main.py:4326–4340, 5355–5516). However, an analyst can also set status `fixed` manually, which can close a linked ADO item without this replay path. Therefore do not describe all closures as regression-proven.

Validated-finding summaries can yield prompt suggestions and export candidate training rows; this is not retraining or deployed-model improvement (src/core/model_improvement.py:14–78, 92–155; SHA256 6516fdb1da7239a38206958e3bfbfa0b043e729e2e8ce7101a826f87f34f54af). Own-engine claim versus integrations. The native-detector claim is supportable for the cited DAST, SAST, SCA and container paths; src/core/predator.py:1–110 (SHA256 08fce778ed7ba25fb52b9518fba2a6335d0c559aae0ab5768eb22634145a176c) describes removal of former wrapped offensive scanners.
