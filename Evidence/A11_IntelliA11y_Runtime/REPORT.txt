INTELLIA11Y NATIVE-ENGINE SYNTHETIC REGRESSION — 11 October 2026

OBSERVED RESULT
Two before/after pairs were executed through the existing API RuleEngine.analyze wrapper, which invokes the native IntelliA11yEngine. Before: 3 confirmed findings and 11 review-required findings. After: 0 confirmed findings and 5 review-required findings. Both pairs produced identical finding lists. No timing/performance conclusion is drawn.
Confirmed finding IDs before: input-label, act-button-accessible-name, act-form-field-accessible-name. These include overlapping coverage of the same input; 3 finding records are not 3 independent barriers. The corrected fixture adds a document language, an associated field label and visible button text. The document-language concern was review-required, not counted among the 3 confirmed findings. Five review-required findings remain, so zero confirmed findings is not accessibility conformance.

METHOD AND SCOPE
The evidence author prepared two synthetic HTML strings and invoked the unchanged native wrapper with WCAG 2.2 AA settings, LLM disabled and best practices disabled. No browser interaction probes or computed-style capture were supplied. This is server-side DOM analysis using JSDOM, not a rendered-browser scan, assistive-technology assessment or full WCAG audit. The fixture correction is deliberate author work, not an AI-generated fix or rule/model update. No application source was changed.
An existing isolated TESTA demonstration database was used. Importing the application database module initiates its startup/migration checks. The knowledge-base lookup reported a missing relation and the optional RAG enrichment was unavailable; this run does not establish RAG behaviour. LLM was disabled throughout. Source result fields labelled pass 3 do not establish model inference. The original execution log is retained privately because it contains machine details; the structured result extract contains actual returned finding IDs, tiers, selectors and counts.
No client records, real user feedback, ADO ticket, model training or autonomous remediation were used. No finding or result was inserted into the dashboard for display. Handoff_Status.txt separately records available installed consumer machinery and why a completed ticket-to-fix lifecycle has not yet been verified.

REPRODUCTION
Provide INTELLIA11Y_API pointing to the existing application api directory and DATABASE_URL pointing to an isolated, already migrated local demonstration database, then run node run-engine.cjs. Installed application dependencies including tsx and jsdom are required. Do not point this harness at a client or shared production database: importing the application module initiates startup/migration checks. Output overwrites files beside the script; copy this historical evidence first. The script does not print or publish the database connection value.
